两套视觉语言，同一个编辑器

mdview 是 Rust 内核 + Tauri 2 + Vue 3 的 Markdown 编辑器，界面元素不多但语义密集：三种视图、一个大纲、一条状态栏、三层浮层。下面两套方案针对同一份功能结构给出不同的材质、圆角与图标语言，切换上方标签可实时对比。

风格 A · HyperOS 4.0
大圆角（窗口 22 / 卡片 18）+ 强毛玻璃，侧栏与正文各成一张浮起卡片； 强调色走蓝→紫渐变；图标 1.85 描边、圆端点、局部 16% 填充形成双色调。
风格 B · macOS + Mica
macOS 控件尺度（窗口 12 / 控件 26px 高）+ Win11 Mica 云母底层； 侧栏为 vibrancy 半透明、正文直接铺在窗口上不画卡片；图标 1.5 细描边线性。
共同约束
正文排版、代码高亮、选区与光标在两侧保持一致 —— 阅读体验不随皮肤变化； 所有交互元素保留键盘焦点环；对比度正文 ≥ 7:1、次要文本 ≥ 4.5:1。

语义差异示例：「源码视图」A 套是 < / > 加一条斜杠，强调代码的密度；B 套只留一对括号，去掉斜杠 —— macOS 在这类抽象语义上更倾向少一个元素。「大纲」A 套三条线起点逐级右移（阶梯感），B 套起点统一、长度递增（列表感）。这类差异不影响识别，但决定了两套图标放在一起时的气质区别。

06

落地到 src/styles/app.css

现有外壳已经是一套「Win11 尺寸 + macOS 配色」的混合体（--chrome: #f6f6f7、30px 标题栏、6px 圆角）。因此 B 套本质是对现状的精修，改动集中在材质与描边；A 套才是结构性重构，需要新增侧栏卡片化与状态栏胶囊两条布局规则。落地时把 A 套放进 [data-skin="hyperos"] 作用域，两套就能共存并实时切换，不必二选一。

已落地为可切换皮肤。两套方案没有替换 src/styles/app.css，而是在它之上加了一层： <html data-skin="macos|hyperos"> 管风格，data-theme 管明暗，两个属性正交， 组合出四种外观。src/styles/skin.css 用 :root[data-skin="hyperos"] 覆盖令牌， 同时把标题栏高度、侧栏宽度、状态栏高度抽成 --chrome-h / --outline-w / --bar-* 四个变量整体换挡，所以侧栏卡片化、状态栏胶囊化不需要复制布局规则。 入口在 视图 → 外观，选择记进 localStorage，首帧由 public/skin-boot.js 提前写属性避免闪变。 默认仍是 macOS —— 没选过的用户升级后观感不变。

实施顺序

第 1 步 · 令牌替换
只改 :root 两块声明与 --font-ui，不动任何布局规则。可立即看到 80% 的风格变化，风险最低。
第 2 步 · 材质与描边
给 .win 加 backdrop-filter 与顶部高光伪元素；浮层统一改用 --pop-bg + 30px 模糊。
第 3 步 · 布局性差异
A 套给 #outline 加外边距与圆角、给 #bar 改胶囊，都挂在 html[data-skin="hyperos"] 下。已按此落地：滚动条轨道改读元素实测边距，胶囊的 10px 外缝不会再被算进轨道。
第 4 步 · 图标落地
现有代码用 lucide-vue-next 与手写 sprite。若要换成自有图标，建议只替换 index.html 里的 sprite（查找栏用），菜单与按钮的 Lucide 组件按同网格重绘后再替换。
一处需要注意：当前 #bar 使用 backdrop-filter: blur(6px) 且贴底全宽，scrollbars.ts 的 edges() 依赖它的实际高度来裁滚动条轨道。改成胶囊（有外边距、浮动）后需确认 getBoundingClientRect() 仍能取到正确下边界，否则纵向滚动条会短一截。
窗口级材质的真实约束：两套方案的"透出桌面"效果都依赖 WebView 之外的系统背景。CSS 的 backdrop-filter 只能模糊 WebView 内部的内容，透不到桌面。若要让窗口真正呈现 Win11 Mica 或 macOS vibrancy，需在 Rust 侧启用系统背景：Windows 调用 DwmSetWindowAttribute 的 DWMWA_SYSTEMBACKDROP_TYPE（Mica / Acrylic），macOS 用 NSVisualEffectView。没有这层支持时，A 套的 --chrome: transparent 会退化成纯白，应改为半透明白并只保留 WebView 内模糊 —— 这也是当前 --bar-bg: rgba(...,.94) 取高不透明度的原因。
